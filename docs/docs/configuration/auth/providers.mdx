Sourcebot supports a wide range of different authentication providers through it's integration with [Auth.js](https://authjs.dev/). This page
highlights how to configure the various supported providers.

If there's an authentication provider you'd like us to support, please [reach out](https://www.sourcebot.dev/contact).

# Core Authentication Providers

### Email / Password
---
Email / password authentication is enabled by default. It can be **disabled** by setting `AUTH_CREDENTIALS_LOGIN_ENABLED` to `false`.

### Email codes
---
Email codes are 6 digit codes sent to a provided email. Email codes are enabled when transactional emails are configured using the following environment variables:

- `AUTH_EMAIL_CODE_LOGIN_ENABLED`
- `SMTP_CONNECTION_URL`
- `EMAIL_FROM_ADDRESS`


See [transactional emails](/docs/configuration/transactional-emails) for more details.

### Custom OpenID Connect provider
---
Any OpenID Connect compliant identity provider can be used for single sign-on. The provider is enabled when `AUTH_CUSTOM_CLIENT_ID`, `AUTH_CUSTOM_CLIENT_SECRET` and `AUTH_CUSTOM_ISSUER` are set. Endpoints are resolved from `<AUTH_CUSTOM_ISSUER>/.well-known/openid-configuration`.

Register `<AUTH_URL>/api/auth/callback/custom` as the redirect URI of the client in your identity provider.

| Variable | Default | Description |
| :------- | :------ | :---------- |
| `AUTH_CUSTOM_CLIENT_ID` | - | Client ID of the application registered in the identity provider. |
| `AUTH_CUSTOM_CLIENT_SECRET` | - | Client secret of the application registered in the identity provider. |
| `AUTH_CUSTOM_ISSUER` | - | Issuer URL of the identity provider. |
| `AUTH_CUSTOM_NAME` | `SSO` | Name displayed on the login button. |
| `AUTH_CUSTOM_SCOPE` | `openid email profile` | Requested scopes. |
| `AUTH_CUSTOM_CLIENT_AUTH_METHOD` | `client_secret_basic` | Token endpoint authentication method, `client_secret_basic` or `client_secret_post`. |
| `AUTH_CUSTOM_CHECKS` | `pkce,state` | Comma separated checks performed during the authorization code flow: `pkce`, `state`, `nonce`. |
| `AUTH_CUSTOM_FETCH_USERINFO` | `false` | Read the user profile from the userinfo endpoint instead of the id token claims. Enable it when the id token does not contain the `email` claim. |
| `AUTH_CUSTOM_ALLOW_ACCOUNT_LINKING` | `false` | Link the account to an existing user with the same email address. Only enable it when the identity provider verifies email addresses. |

The identity provider must return an `email` claim; sign-in is rejected otherwise. Set `AUTH_CREDENTIALS_LOGIN_ENABLED` to `false` to make the custom provider the only login method.

<Note>
If the identity provider uses a certificate signed by a private CA, point `NODE_EXTRA_CA_CERTS` to the CA certificate.
</Note>
